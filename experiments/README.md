# Experiments

Measurements of what this fork does, produced by running it.

`results/RESULTS.md` is generated by `run_all.py` and is not edited by hand, so
it cannot drift from the code that produced it. Every run records the build it
ran against -- `S4.__version__` and the install's `BUILD-INFO.txt` -- because a
number without a build is not a result.

```bash
python run_all.py            # run everything, rewrite results/RESULTS.md
python run_all.py exp01      # one experiment, to stdout, nothing written
```

Exit status is non-zero if any experiment came out other than expected, so this
is usable as a check and not only as a document.

| | |
|---|---|
| `exp01_plane_interface` | a plane interface against the closed-form Fresnel coefficients |
| `exp02_ellipse_identity` | an ellipse with equal half-widths against the circle it is |
| `exp03_geometry_gate` | mean permittivity against the exact value, for four structures |
| `exp04_convergence` | R+T as a convergence indicator, and requested against actual order counts |

## How this differs from `validation/`

`validation/` asks whether the port and the fixes are correct: `probe.py` and
`compare.py` compare two builds of S4 against each other, and `diagnostics.py`
asserts behaviour that must hold. Those are pass/fail and they answer "is this
right".

Here the question is "what does it do", and the answers are numbers meant to be
read. Where possible they are measured against something that is not S4 -- a
closed form, an exact geometric quantity, an identity the shape must satisfy --
because two builds of the same program agreeing tells you they agree, not that
they are right.

## Adding one

A module exposing `NAME` and `run()`, listed in `EXPERIMENTS` in `run_all.py`.
`run()` returns a dict with `headers`, `rows` (strings, already formatted),
`summary`, and `pass`; `extra` adds a second table with a `caption`. The
module docstring becomes the section text, so it should say what the experiment
establishes and why that follows -- not how the code works.
